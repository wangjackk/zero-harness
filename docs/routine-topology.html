万物皆 routine 按两份真实清单画的：名字都能 grep 到，不是示意图

“万物皆 routine”不是“所有东西都写成函数”，而是：agent、工具、技能库、车身、提示词、乃至框架自己的加载器和热重载器， 都在同一张注册表里，用同一个名字、同一套生命周期（create / start / stop）、同三种投递语义（call / req / publish）被调用。 图里 45 个方块是 123 个注册名里的骨架（同名族折叠，标了 ×N）。点任意方块，看它落在哪个文件、 凭什么算 routine；把右边连线点亮/点灭，能单独看一条关系。

判据：凭什么说它是 routine

  1. 有名字：name 是类字段，注册名就是标签名（car/move → <car/move/>）
  2. 有 schema：入参是 pydantic 模型，能力清单由它渲染，模型照着写标签
  3. 有生命周期：create / start / stop / 驱逐；passive 的注册即拉起
  4. 同一条投递口：别人用 call（父子实例）、req（p2p 事件）、publish（扇出）找它
  5. 同一处可见：routine/list 能列出来，前端 /run_routine 能直接跑

五条缺一条就不算。所以 memory 不是 routine（见图中虚框反例）， 而“把历史压成摘要”是（xml_condenser_agent）—— 单元是动作，不是数据。

两条读图提示。① 方块颜色 = 类别，右上小圆点 = 在哪个进程注册：● zero 独有、 ● moss 独有、● 两边都有（19 个，多数是 car/*、read_image、bus_listener 这类“同一具身体的两个入口”）。 ② ×N 是折叠掉的注册名个数，都是实数：car/* 14、bb/* 13、skill/* 8、 ssh/* 5、chan/* 5、控制原语 4、web_* 2。
没画进来的条目（不是遗漏，是重复形状）：agent_hub 的三个查询桥（types / running_agents / preset/*）、 models / tree / presets 这几个“事实源 hub”、agent/rid / agent/state / agent/history、 xml/agent 的六个管理动词（create / list / stop / resume / delete / set_routine_alias）——它们是同一张表里的条目， 全画进来这张图就退化成一份清单。
没画的一类边：publish 扇出不产生 routine→routine 的固定连线（订阅表挂在 kernel 上，按 topic 动态 mount）。 画出来就是一团“谁都可能连谁”的噪声——它是投递语义，不是拓扑。同理 kernel 的模块树（tree.json）管“身体有哪些部位”， 和“能力有哪些名字”是两张表，别混。
