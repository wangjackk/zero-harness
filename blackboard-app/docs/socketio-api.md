# 黑板 Socket.IO 接口

给**用户侧**看的线协议。只要握手和 JSON 形状对上，用什么语言写都行；本文只定义接口，不规定实现，也不假设对方是谁——模型、脚本、人操作的界面，都算用户侧。

- 传输：Socket.IO v4（Engine.IO 4），默认 path `/socket.io/`，**走 websocket**，不降级 polling。
- 服务端：`bun run dev` 起在 `http://localhost:3001`（`/health` 返回 `ok`）。
- 黑板侧（浏览器）：`http://localhost:5173`，也是当 viewer 连同一个端口。
- payload 都是普通 JSON object（Python 侧就是 dict），没有二进制。

**黑板是静态的**：没有播放、没有队列、没有时间轴。动作到了就画，画完就留在那儿，直到你 `erase`。节奏完全由用户侧控制——想慢就分条发、条与条之间自己等。**默认是空白板**，服务端自己什么都不画。

---

## 1. 两种角色、三个事件

一块黑板上只有两种角色，靠**握手 auth** 区分：

| 角色 | 谁 | auth | 能收 | 能发 |
|---|---|---|---|---|
| `viewer`（黑板侧） | 画的那个（浏览器） | 不填 / 任意 | `bb:down` | `bb:up`（input / abort / objects） |
| `user`（用户侧） | 说的是什么、指哪个 | `{"role":"user"}` | `bb:objects` | `bb:up`（**actions** / abort） |

| 事件 | 方向 | 用途 |
|---|---|---|
| `bb:up` | 客户端 → 服务端 | 上行。用户侧用它推 `actions` |
| `bb:down` | 服务端 → 黑板侧 | 下行。动作流 / 打断 / 对象表重置 |
| `bb:objects` | 服务端 → 用户侧 | 对象表回灌（黑板侧量出来的 bbox） |

握手必须带 `{"role":"user"}`，否则被当成 viewer：收不到对象表，而且推上去的 `actions` 会被**静默丢弃**（服务端只认用户侧发的动作）。

有用户侧连接时，服务端不播内置演示流。实际上**演示流默认就是关的**：没人推动作，板子就是空的。（想单独看渲染效果：服务端用 `BB_DEMO=1` 启动，且用户侧一连上就自动让位。）

## 2. 推动作（唯一必须会用的事件）

```json
{
  "type": "actions",
  "items": [
    { "id": "a1", "act": { "do": "write", "text": "斜率就是变化率", "at": [0.12, 0.28], "size": "l" } }
  ]
}
```

- `type` 必须是 `"actions"`。
- `items` 里**每个动作都必须有 `id`**（字符串，自己起名，见 §7）。
- 服务端会给整条消息盖一个 `seq` 再广播给所有黑板侧。**`seq` 由服务端分配，你不要发**，发了也被覆盖。`seq` 是服务端进程级自增，不按连接重置——别假设它从 1 开始。
- 一次 emit 几个动作都行，但**同一条消息里的动作是同时开始的**（§8）。要"一笔一笔来"，就拆成多条消息。

## 3. 十二个动作

`act` 是一个 discriminated union：靠 `do` 分支。下表是全部合法字段，多传的键会被忽略。

| `do` | 字段 | 默认 | 画出来是什么 |
|---|---|---|---|
| `write` | `text: string`、`at: Anchor`、`size?: "s"\|"m"\|"l"` | `m` | 逐字扫出的一段手写文字 |
| `line` | `from: Anchor`、`to: Anchor`、`dash?: boolean` | 实线 | 一条直线 |
| `arrow` | `from: Anchor`、`to: Anchor` | — | 带箭头的直线（主干 + 两撇） |
| `rect` | `at: Anchor`（**中心**）、`w: number`、`h: number`、`round?: number` | `round 7` | 标准矩形，**一条笔迹**绕一圈；`w === h` 就是正方形 |
| `poly` | `points: Anchor[]`、`close?: boolean`、`round?: number` | `round 7` | 折线 / 多边形，**一条笔迹**，角上自带走圆 |
| `circle` | `at: Anchor`（圆心）、`r: number` | — | **标准圆**：闭合、等宽，像素上宽高相等 |
| `ellipse` | `at: Anchor`（圆心）、`rx: number`、`ry?: number` | `ry = rx` | 标准椭圆 |
| `ring` | `around: string`（对象 id）、`pad?: number` | `14` | **强调用的手绘圈**：留缺口、带抖动，围着对象画一圈。**不是几何圆** |
| `underline` | `around: string`、`pad?: number` | `8` | 在某对象下方划一条 |
| `point` | `at: Anchor` | — | 一个小圆"点一下"（直径 11px） |
| `erase` | `around: string \| "all"` | — | 擦掉一个对象；`"all"` 清空整块板 |
| `pixel` | `ops: PixelOp[]` | — | 直接改像素，无动画（§4） |

### `circle` 和 `ring` 是两件事，别混

| | 是什么 | 长什么样 | 怎么给位置 |
|---|---|---|---|
| `circle` | 几何图形 | 闭合的真圆，抖动 < 1px | 圆心 `at` + 半径 `r` |
| `ring` | 批注强调 | 手画的圈，留 6~10% 缺口，贴字迹外扩 | `around` 指向已有对象 + `pad` |

要在字下面画个圆说明"这就是圆形"，用 `circle`；要把黑板上的某句话圈起来强调，用 `ring`。拿 `ring` 当圆画，画出来一定不圆——它是本子上的圈，不是圆规画的圆。

```json
// 标准圆：圆心 (0.5,0.4)，半径 = 短边 × 0.12
{ "do": "circle", "at": [0.5,0.4], "r": 0.12 }

// 写在 a1 下面：图形贴着字底外边缘放，水平居中，不压字
{ "do": "circle", "at": "below:a1", "r": 0.09 }

// 强调：把 a1 那句话圈起来
{ "do": "ring", "around": "a1", "pad": 18 }
```

### 位置和长度，两个单位

这是最容易画歪的一处，必须分清：

| 量 | 单位 | 覆盖面 |
|---|---|---|
| **位置** | 归一化 `[0..1]`，x 按画布宽、y 按画布高 | `at`、`from`、`to`、`points` 里的坐标 |
| **长度** | **画布短边** `min(W,H)` 为单位 | `r`、`rx`、`ry`、`w`、`h` |

位置按轴分开是对的（`[0.5,0.5]` 就是正中），但长度**绝不能**按轴归一化：那样 `w:0.3, h:0.3` 在宽屏上会画成长方形，圆会变成横着压扁的椭圆。用短边做单位，`0.3` 宽和 `0.3` 高就是同一个长度——圆是圆，方是方。

### 画形状不要用 line 拼

想画三角形、方框、任何折线形状，**用 `poly` / `rect`，不要发多条 `line`**。

原因不是风格问题：每条 `line` 是**独立的一笔**，各自两端收细、各自带手抖，两笔在角上对不齐，看起来就是断的。而 `rect` / `poly` 是**一整条连续笔迹**，角上做了一圈小圆角过渡（`round`，默认 7px），笔迹本身没有接缝。

```json
// 三角形：三个点，一笔画完
{ "do": "poly", "points": [[0.5,0.16],[0.32,0.52],[0.68,0.52]], "close": true }

// 正方形（w === h），at 是中心
{ "do": "rect", "at": [0.35,0.33], "w": 0.3, "h": 0.3 }

// 圆心 (0.5,0.4)、半径 0.18（短边单位）的椭圆
{ "do": "ellipse", "at": [0.5,0.4], "rx": 0.18, "ry": 0.11 }
```

`points` 里的每一项都是 Anchor，所以可以引用已有对象（`"below:a1"`），不只是归一化坐标。

`close: true` 会绕回起点并**略微过冲**一小截（人画框就是这么收笔的），所以四个角是实的，不会有缺口。`circle` / `ellipse` 本来就闭合。

单位与时长：

- `pad` 是**画布像素**，不是归一化值。1600×900 下一行 `l` 文字高约 70px，`pad:14` 差不多留一指宽。
- 数值参数（`pad` / `w` / `h` / `r` / `rx` / `ry` / `round`）传数字或数字字符串都行，黑板侧会转一次；非法值退回默认。**但别依赖它**——传 `null` 或空串会得到默认值，看上去像"参数没生效"。
- `r` / `rx` / `ry` / `w` / `h` 以**画布短边**为单位，见上一节。
- `size` 字号 = `min(画布宽, 高) × {s:0.038, m:0.055, l:0.078}`。1600×900 下 `l ≈ 70px`、`m ≈ 50px`、`s ≈ 34px`。
- 每个动作自带入场动画，时长由黑板侧定：`write` 每字约 0.155s（8 个字 ≈ 1.3s），`line` 按长度 0.3~1.6s，`rect` / `poly` / `circle` / `ellipse` 1.6s 左右，`point` 0.22s。**这个时长不可配**。
- 没有 `wait` 动作。要停顿，就在两次 emit 之间自己等（服务端不替你排期）。

`erase` 有两种模式：

- `{"do":"erase","around":"a1"}` —— 擦掉 **a1 这个对象的全部笔迹**（写字是逐字多条，一次全删），对象表同步删掉这条记录。板子从笔迹日志重建，所以不会误伤旁边的对象。
- `{"do":"erase","around":"all"}` —— 清空整块板（笔迹 + 对象表）。

幂等：擦一个不存在的 id 什么也不发生，不报错。代价：按对象擦要重建整块位图，笔迹很多时是一次性的几十毫秒——单次调用无感，别在一帧里连擦几十个。

想擦一块**区域**（而不是某个对象），用 §4 的 `pixel` + `clearRect`。

## 4. 原子像素操作（`pixel`）

语义动作画的是"东西"，`pixel` 画的是"像素"。它是唯一的低层出口：不参与布局、不登记对象、没有入场动画，到了就改位图。

```json
{
  "do": "pixel",
  "ops": [
    { "op": "clearRect", "x": 0.62, "y": 0.10, "w": 0.30, "h": 0.12 },
    { "op": "fillRect",  "x": 0.62, "y": 0.10, "w": 0.30, "h": 0.12, "color": "#f2efe2", "alpha": 0.08 },
    { "op": "pixel",     "x": 0.10, "y": 0.50, "color": "#ff5555" },
    { "op": "image",     "x": 0.70, "y": 0.60, "w": 0.20, "h": 0.15, "src": "data:image/png;base64,..." }
  ]
}
```

| `op` | 字段 | 效果 |
|---|---|---|
| `clearRect` | `x,y,w,h` | 抹成透明（黑板擦） |
| `fillRect` | `x,y,w,h`、`color?`、`alpha?` | 填一块色 |
| `pixel` | `x,y`、`color?`、`alpha?` | 一个像素 |
| `image` | `x,y,w,h`、`src` | 贴图（data URL 或同源 http） |

规则，全部要记：

- **坐标也是归一化 `[0..1]`**，和语义动作一致；黑板侧按当前画布尺寸换算。
- **`ops` 按数组顺序执行**，顺序有意义（先 `clearRect` 再 `fillRect`）。
- **对齐到整像素**（向外取整到矩形覆盖的整像素）。所以同一块区域 `fillRect` 再 `clearRect` 能精确抵消、不留毛边；反过来画 1px 细线会觉得比预期粗一点点，这是像素层的正常代价。
- **它改的是位图本身，不是叠一层。** 没有"撤销这一笔"的概念：擦掉的内容不会自己回来，要恢复就重发内容。（黑板在重建位图时会按日志重放 ops，顺序一致，但那是内部实现，不是给你的回滚能力。）
- 不做动画、不等待。发到就生效，下一帧就能看见。
- `image` 是**异步**的：图没加载完那一帧不画，加载完自动重绘一次。跨域图片会污染画布（`getImageData` 会抛错），用 data URL 最稳。
- `alpha` 是 0~1，缺省 1。`color` 缺省是粉笔白。

`pixel` 的 `id` 照样要唯一，但它**不登记到对象表**，所以事后不能 `ring around` 它，也不会出现在回灌快照里。

## 5. Anchor：坐标只有两种写法

```ts
[number, number]              // 归一化 [x, y]，0~1，相对画布
"right-of:<id>"               // 某对象右侧
"left-of:<id>"
"above:<id>"
"below:<id>"
```

规则：

- **`write` 的 y 是基线（落笔点），不是包围盒顶边。** 写 `y=0.28` 意味着字坐在 28% 高度那条线上，字身往上长。
- **[x, y] 会被钳到 `x∈[0.01,0.99]`、`y∈[0.06,0.96]`**，防止写出画布。**钳制只防越界，不防重叠**——重叠要自己排（§6 给对象表）。
- **锚点用在图形上时是"贴边"的**：`"below:a1"` 给 `circle` / `rect` 时，图形的外边缘正好离 a1 的下边缘一个 GAP，并在水平方向**居中**，所以不会压到字上。用在 `write` 上则是基线 + 左对齐。
- 锚点前缀只认 `right-of` / `left-of` / `above`，**其它任何写法（包括拼错的 `rigth-of`）都会按 `below` 处理**。拼错不会报错，只会静默落到下方。
- 引用的 id 不存在 → 静默退回画布**正中心** `[0.5, 0.5]`。所以 `ring` / `underline` 引错 id 时不会报错，只会圈在中间——看到这种结果先查拼写。
- `ring` / `underline` 的 `around` **必须是对象 id**，不接受数组坐标。

「字在上、图在下」的典型写法，一次挂靠就够：

```json
{ "id": "a1", "act": { "do": "write",  "text": "圆形", "at": [0.17, 0.42], "size": "m" } }
{ "id": "c1", "act": { "do": "circle", "at": "below:a1", "r": 0.09 } }
```

要强调那句话（而不是画个圆），把第二条换成 `{ "do": "ring", "around": "a1", "pad": 18 }`。

推荐写法：先用 `[x,y]` 写出第一句，之后一律用 `below:` / `right-of:` 挂靠，布局就不会随内容长度崩掉。

## 6. 对象表回灌（决定你写不写得好）

黑板侧在收到动作后约 220ms，把**全量快照**通过 `bb:up{type:"objects"}` 上报，服务端转成 `bb:objects` 推给所有用户侧连接：

```json
{
  "type": "objects",
  "from": "u2C-X0agsl8u249wAAAC",
  "seq": 12,
  "objects": [
    { "id": "a1", "kind": "text", "text": "斜率就是变化率", "box": [0.118, 0.191, 0.462, 0.098] },
    { "id": "a3", "kind": "stroke", "box": [0.12, 0.62, 0.36, 0.004] }
  ]
}
```

- **`from` 是这块黑板的连接 id**。同时开着多个标签页时，会有多块黑板各自上报，顺序还不固定——只认你要控制的那一块。（黑板侧在 `connect` 之后才拿得到自己的 id，第一次可以按"谁的值对得上"反推。）
- `box` = `[x, y, w, h]`，归一化。**只有黑板侧能量得准**（依赖真实字体和字号），别自己算。
- `kind: "text"` 带 `text`（原文）；`kind: "stroke"` 不带。
- id 就是**你发的 id**，所以要自己维护成唯一、稳定、可读（建议 `a1,a2,a3…` 递增）。
- `write` / `line` / `rect` / `poly` / `circle` / `ellipse` 进对象表；`arrow` / `ring` / `underline` / `point` / `pixel` **不进**。想让箭头以后能被引用，就用 `line` 代替，或引用它旁边的文字。
- `erase` 掉的对象会从表里消失，此后引用它 → 落到画布中心。
- 是**快照不是增量**：每次收到就是当前板上全部对象，直接替换本地那份。
- 服务端**不缓存**：晚连上来的用户侧拿不到历史，要等下一条动作才触发一次上报。所以第一轮没有上下文是正常的，从 `[x,y]` 起步。

这张表的用途很直接：让你知道哪句话写在哪、多宽多高，从而说出"圈住 a1"而不是瞎猜坐标。要引用上一句，就必须留一份最新的 `objects`。

## 7. id 的三条硬规则

1. **唯一**。同一个 id 再登记会覆盖旧记录，锚点就指到错的东西上。
2. **稳定**。发出去的 id，后续锚点、`ring`、`underline` 都靠它，不要中途换名。
3. **不复用**。`erase all` 会清空对象表；清完从头编号，不要拿旧 id 指新内容。

## 8. 没有时间轴：节奏全在用户侧手上

这是本接口最重要的一条，理解它就不会踩坑：

- 黑板只维护"当前画面"，**不排队、不排期、不能暂停/回放/拖动**。
- 动作到达即开始入场动画，各自独立。**同一条消息里的多个动作同时开始**——所以一条消息里别写"先写这句，再圈那句"，圈会边写边圈（位置是对的，因为 bbox 在收到时已登记，但视觉上重叠）。
- 想要"写 → 停 → 圈 → 停"，就发多条消息，条与条之间自己等：
  - 粗等：`sleep(1.2)`（按字数估算，8 字 ≈ 1.3s）；
  - 准等：发完等到下一条 `bb:objects` 回来再发下一条。回执意味着黑板侧已经把上一批处理完并登记好对象，这是唯一的同步点。
- 连发太快不会导致积压（没有队列），而是**所有笔同时开画**：画面会乱，但不会滞后。这是"静态黑板"换来的代价，刹车在用户侧。
- `abort` 只做一件事：把**正在画**的笔就地定格（留下的半笔就是被打断的痕迹），已经画完的一个字都不动。

```json
{ "type": "abort" }
```

`abort` 也走 `bb:up`，用户侧可以发。

## 9. 完整时序（一次最小交互）

```
用户侧 ──connect(auth={role:"user"})──▶ server
                                        └─ 不播演示流，画面交给用户侧
用户侧 ──bb:up {type:"actions", items:[write "斜率", at [0.12,0.28]]}──▶ server
                                                                        ├─ seq += 1
                                                                        └─ bb:down ▶ 黑板侧立刻开写（约 0.3s）
黑板侧 ──bb:up {type:"objects", seq, objects:[{id:"a1",...,box}]}──▶ server
                                                                    └─ bb:objects ▶ 用户侧（此时可以基于这张表发下一条）
用户侧 ──bb:up {type:"actions", items:[ring around:"a1"]}──▶ server   （现在圈，位置一定对）
```

板子不清空就一直叠着。要重来就发 `{"do":"erase","around":"all"}`。

## 10. 九个必须知道的现状与坑

1. **服务端不校验 payload**。坏 JSON（缺 `do`、`text` 不是字符串）不会报错，黑板侧 `switch` 匹配不到就静默跳过。**发送侧的 schema 要自己守**，否则表现就是"发了没反应"。
2. **没有 ack，没有错误回报**。`emit` 成功只代表字节送到服务端，不代表画出来了。要确认效果，只能等 `bb:objects` 里出现（或消失）对应 id，或者看画面。
3. **多块黑板会一起上报**。同一台机器开着两个标签页，`bb:objects` 就会有两种 `from` 交替出现——按 `from` 过滤，否则你会把别人的板子当成自己的。
4. **多用户侧连接会互相抢**。每个连接都能推、都能收到同一份对象表，`seq` 是全局的。调试时只留一个，否则会出现"内容多了一半"。
5. **重连不补发**。服务端不存历史。断线重连后想恢复画面，得自己重发一遍完整内容（或让黑板侧清屏后重来）。
6. **对象表不带箭头/圈/椭圆/pixel**。它们不进表，所以画了圈之后引用不到圈本身；`pixel` 画的像素也永远不会出现在回灌里。
7. **`ring` / `underline` 引用不存在的 id 会被跳过**，只在黑板侧的浏览器控制台留一条 warn，不会回报给你。发之前先确认对象表里有那个 id 的分量：第一轮 `bb:objects` 还没到，此时板上什么都没有，`ring` 必然落空。
8. **`seq` 是服务端进程级自增**，不按连接重置，别假设它从 1 开始。
9. **顶层的 `sync` 字段目前无效**。`{type:"actions", sync:{start,end}}` 会被服务端原样透传，黑板侧不消费——它是给语音对齐预留的，现在没有时间轴，对齐手段是用户侧自己控制 emit 的时刻。

## 11. 想换掉这个 Node 服务端（另一条路）

协议与服务端实现无关，用别的语言顶掉它只需满足三条：

1. 监听同一端口，Socket.IO v4 / EIO=4，允许 websocket 传输、`cors.origin: "*"`。
2. 握手 `auth.role === "user"` 的连接只收 `bb:objects`、只发 `bb:up{type:"actions"}`；不带 role 的连接当 viewer，把动作以 `bb:down` 广播给它。
3. `seq` 由服务端自增盖戳（黑板侧不依赖它排序）。

字段定义以 `shared/protocol.ts` 为准——那是唯一权威，本文是它的散文版。
